tiny_ca.ca_factory.factory module¶

factory.py

X.509 certificate factory: issues end-entity certificates, builds self-signed CA certificates, generates CRLs, and validates certificate chains.

This module contains a single public class, CertificateFactory, whose only responsibility is cryptographic construction. It never touches the filesystem, the database, or any business-logic layer.

SOLID notes¶

SRPCertificateFactory handles cryptographic generation only.

File persistence → BaseStorage. DB registration → BaseDB.

OCPNew X.509 extension types are added in _build_extensions without

modifying any other method.

LSP : Any ICALoader implementation can be swapped in transparently. ISP : SerialWithEncoding and CertLifetime are separate utility modules;

only the symbols needed here are imported.

DIPCA material is provided through the ICALoader Protocol injected at

construction time; the factory never instantiates a loader itself.

class tiny_ca.ca_factory.factory.CertificateFactory(ca_loader, logger=None, crl_distribution_points=None, ca_issuers_urls=None, ocsp_urls=None)[source]¶

Bases: object

Cryptographic factory for X.509 certificates, CSRs, and CRLs.

CertificateFactory is the single source of all certificate-generation logic in the library. It accepts an ICALoader at construction time and uses the CA certificate and key it provides to sign all issued artefacts.

Responsibilities¶

  • Generate self-signed root CA certificates (build_self_signed_ca).

  • Issue end-entity certificates signed by the loaded CA (issue_certificate).

  • Issue subordinate CA certificates (issue_intermediate_ca).

  • Build and sign Certificate Revocation Lists (build_crl).

  • Validate certificates directly (validate_cert) or through intermediates (validate_chain).

Out of scope¶

  • Writing any files to disk.

  • Recording certificates in a database.

  • Business-level rules (duplicate CN detection, rotation policies, etc.).

build_crl(revoked_certs, days_valid=1, crl_number=None)[source]¶

Build and sign a Certificate Revocation List from the provided records.

The CRL always carries the CRLNumber (RFC 5280 §5.2.3, mandatory) and AuthorityKeyIdentifier extensions. Each entry includes the CRLReason entry extension when the stored reason is meaningful (unspecified is omitted, as RFC 5280 §5.3.1 recommends).

Parameters:

  • revoked_certs (Iterable) – Revoked certificate records as returned by BaseDB.get_revoked_certificates — ORM records, SQLAlchemy rows or (serial, revocation_date[, reason]) tuples.

  • days_valid (int) – Number of days until nextUpdate. Default: 1.

  • crl_number (int | None) – Explicit CRL sequence number. None derives a monotonically increasing number from the current time in microseconds, so no external state is required.

Returns:

The signed CRL object. The caller is responsible for persisting it.

Return type:

x509.CertificateRevocationList

static build_self_signed_ca(common_name='Internal CA', organization='My Company', country='UA', key_size=2048, days_valid=3650, valid_from=None, logger=None, key_algorithm=KeyAlgorithm.RSA)[source]¶

Generate a self-signed root CA certificate and its private key.

This is a @staticmethod — it requires no loaded CA because the resulting certificate is its own issuer. It is typically called once during bootstrap to establish the trust anchor for the PKI.

The generated certificate includes: - BasicConstraints(ca=True) — marks it as a CA certificate. - KeyUsage with key_cert_sign and crl_sign set to True. - SubjectKeyIdentifier derived from the public key.

Parameters:

  • common_name (str) – Common Name (CN) for the CA Subject / Issuer fields.

  • organization (str) – Organization (O) field.

  • country (str) – Two-letter ISO 3166-1 alpha-2 country code (C field).

  • key_size (int) – RSA key length in bits (ignored for EC / Ed25519).

  • days_valid (int) – Validity period in calendar days. Default: 3650 (≈10 years).

  • valid_from (datetime.datetime | None) – Start of the validity period. None uses the current UTC time.

  • logger (Logger | None) – Optional logger. Falls back to DEFAULT_LOGGER.

  • key_algorithm (KeyAlgorithm) – Algorithm of the CA key pair. Default: RSA.

Returns:

(certificate, private_key) — both must be persisted by the caller.

Return type:

tuple[x509.Certificate, PrivateKey]

Raises:

InvalidRangeTimeCertificate – If the computed expiry date is already in the past.

cosign_certificate(cert, days_valid=None, valid_from=None, serial_type=None)[source]¶

Re-sign an existing certificate with this CA’s key and certificate.

The new certificate preserves the original Subject, public key and v3 extensions, but replaces the Issuer, the issuer-bound extensions (AKI, CRL distribution points, AIA) and the serial number. The validity window is preserved unless days_valid is given.

Note

This operation does not verify that the original certificate was valid or trusted before co-signing.

Parameters:

  • cert (x509.Certificate) – The source certificate.

  • days_valid (int | None) – Override the validity duration; None keeps the original window.

  • valid_from (datetime.datetime | None) – Start of the overridden window (ignored when days_valid is None).

  • serial_type (CertType | None) – Serial prefix for the co-signed certificate. None uses CertType.CA for CA certificates and CertType.SERVICE otherwise.

Raises:

InvalidRangeTimeCertificate – If days_valid is provided and the computed expiry is in the past.

Return type:

Certificate

issue_certificate(common_name, serial_type=CertType.SERVICE, key_size=2048, days_valid=365, valid_from=None, email=None, is_server_cert=False, is_client_cert=False, san_dns=None, san_ip=None, key_algorithm=KeyAlgorithm.RSA)[source]¶

Issue a signed end-entity certificate for the given subject parameters.

Workflow: 1. Generate a fresh key pair (key_algorithm). 2. Build the Subject x509.Name from CA base info + common_name / email. 3. Create a CSR signed with the new private key. 4. Assemble X.509 extensions (KeyUsage, EKU, SAN, SKI, AKI and — when

configured — CRLDistributionPoints / AuthorityInformationAccess).

  1. Sign the certificate with the CA key from self._ca.

Parameters:

  • common_name (str) – Common Name (CN) for the new certificate’s Subject.

  • serial_type (CertType) – Certificate category used when encoding the serial number.

  • key_size (int) – RSA key length in bits (ignored for EC / Ed25519).

  • days_valid (int) – Validity period in calendar days. Default: 365.

  • valid_from (datetime.datetime | None) – Start of the validity period. None uses the current UTC time.

  • email (str | None) – Optional email address added as an emailAddress Subject attribute.

  • is_server_cert (bool) – Adds ServerAuth EKU and includes common_name as a DNS SAN.

  • is_client_cert (bool) – Adds ClientAuth EKU.

  • san_dns (list[str] | None) – Additional DNS names for the Subject Alternative Name extension.

  • san_ip (list[str | IPv4Address | IPv6Address] | None) – IP addresses for the Subject Alternative Name extension.

  • key_algorithm (KeyAlgorithm) – Algorithm of the new key pair. Default: RSA.

Returns:

(certificate, private_key, csr).

Return type:

tuple[x509.Certificate, PrivateKey, x509.CertificateSigningRequest]

Raises:

InvalidRangeTimeCertificate – If the computed expiry date is already in the past.

issue_intermediate_ca(common_name, key_size=4096, days_valid=1825, valid_from=None, path_length=0, organization=None, country=None, key_algorithm=KeyAlgorithm.RSA)[source]¶

Issue a subordinate (intermediate) CA certificate signed by this CA.

The resulting certificate has BasicConstraints(ca=True) and KeyUsage(key_cert_sign=True, crl_sign=True). path_length limits how deep the sub-hierarchy can go (0 = may only sign leaves, None = unlimited). When configured, the CRL distribution point / AIA of this CA are included so the intermediate itself can be checked for revocation.

renew_certificate(cert, days_valid=365, valid_from=None)[source]¶

Issue a renewal of cert with a fresh validity window but the same Subject, public key, and extensions.

Renewal re-uses the existing public key — appropriate when the key has not been compromised. The renewal receives a new serial number whose type prefix is preserved from the original (e.g. a renewed DEVICE certificate stays DEVICE).

validate_cert(cert)[source]¶

Verify that cert was issued directly by this CA, is within its validity window, and carries a cryptographically correct signature.

Signature verification uses Certificate.verify_directly_issued_by and therefore works for RSA (PKCS#1 v1.5 and PSS), ECDSA and Ed25519. For certificates issued by an intermediate CA use validate_chain().

Raises:

ValidationCertError – If the issuer, validity window or signature check fails.

Return type:

None

Parameters:

cert (Certificate)

validate_chain(cert, intermediates=())[source]¶

Validate cert up to this CA, optionally through intermediate CAs.

For every link the method checks the validity window, the signature, that the issuer is a CA (BasicConstraints.ca and KeyUsage.key_cert_sign) and that path_length constraints are respected. The chain must terminate at this factory’s CA certificate (the trust anchor).

Parameters:

  • cert (x509.Certificate) – The certificate to validate (usually a leaf).

  • intermediates (Sequence[x509.Certificate]) – Untrusted intermediate CA certificates that may be needed to build the path. Order does not matter.

Returns:

The validated path, leaf first and the CA root last.

Return type:

list[x509.Certificate]

Raises:

ValidationCertError – If no valid path to the CA exists.
